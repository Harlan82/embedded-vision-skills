# Center Object → YOLO ZIP（中心目标自动标注 → 平台可导入数据集）

## Overview

把一批"**某个物体被摆在画面中心附近、背景干净**"的照片，自动变成带检测标注的
YOLO 数据集，并打包成 Ultralytics Platform 能直接上传的 ZIP。

**为什么不默认用 SAM：** 当满足"单目标 + 背景与目标颜色/亮度可分 + 目标居中"三个条件时，
HSV 前景分割 + 几何判据的精度高于通用分割模型，速度约快两个数量级（毫秒级 / 张），
且**零模型下载**。SAM 类模型需要点或框提示（prompt），在"自动找中心物体"这个目标上
反而要额外构造提示、再过滤掩膜，链路更长、更慢、更易错。

**三条硬原则（来自实际踩坑）：**

1. **判据必须来自实测分布，不能拍脑袋。** 先用 `calibrate.py` 统计面积占比 / 宽高比 /
   填充率的真实分位数，再定阈值。凭直觉设 `min_area` 会把四周杂物的 2% 小块当成目标。

2. **必须输出可视化审计图。** 不能只给"命中 N 张"就宣称完成。要拼一张含检测框的图让
   用户肉眼核对，尤其是**未命中样本**和**面积异常大/小的样本**——它们往往是真目标被误杀，
   或杂物被误当目标。

3. **绝不静默丢样本。** 未命中要逐个列出文件名，并让用户看到它们到底长什么样。
   宁可多问一句"这几张请确认"，也不要悄悄少标。

## When To Use

- 用户给一个图片文件夹，说"识别画面中心的东西，标注成 `<class>`"。
- 典型诉求是"没有 SAM 就自己写脚本"。
- 用户要"打包成 ultralytics platform 可导入的 zip"。
- 场景特征：固定机位、白底/纯色转盘、单个工件、位置大致居中。

**不适用：** 目标不居中（任意位置多目标）、背景与目标同色、目标互相遮挡。此时应改走
真分割模型（SAM 2 / FastSAM）或人工标注。

## Quick Start

第 1 步 · 标定阈值（**先做，不要跳**）：
```bash
python scripts/calibrate.py --src <图片目录> [--top 40]
```
输出 `calib.txt`：候选数量，面积占比 / 宽高比 / 填充率的 min/p50/p95/p99/max，
**以及两组关键清单**——"面积最大的前 N 个候选"和"面积 2%~4% 的候选"。
固定杂物会在这两份清单里呈现**高度一致的 center / box**，一眼可辨。

第 2 步 · 构建数据集并打包：
```bash
python scripts/build_yolo_zip.py --src <图片目录> --cls class_9 --zip <输出.zip>
```
可选参数：`--work`（默认 `<zip名>_ds`）、`--val-ratio`(0.15)、`--sat-min`(60)、
`--val-max`(90)、`--area-lo`(0.03)、`--area-hi`(0.15)、`--ratio-max`(2.0)、
`--fill-min`(0.35)、`--center-box`(0.33)、`--edge-margin`(0.04)、`--center-w`(0.05)、
`--seed`(42)。

产出：
```
<zip>
├── data.yaml
├── images/train/*.jpg
├── labels/train/*.txt
├── images/val/*.jpg
└── labels/val/*.txt
```
同时输出 `<zip名>_build.txt`（命中/未命中统计）与 `<zip名>_audit.png`（检测框拼图）。

第 3 步 · 校验 ZIP：
```bash
python scripts/verify_zip.py --zip <输出.zip> [--audit <拼图路径>]
```
检查：CRC、images/labels 一一对应、标签五元组格式、归一化坐标落在 (0,1) 开区间、
`data.yaml` 内容。**必须看审计图**，确认框贴住目标。

> 实测性能：六百余张 480×480 全流程约 10 秒（含复制与压缩），无需 GPU、无需模型下载。

## 判据（核心逻辑）

对每张图：

1. **前景分割**：`fg = (S > SAT_MIN) | (V < VAL_MAX)`。白底 S 很低（通常 <40），
   彩色工件 S 高；`V < VAL_MAX` 用来补捉深色/黑色工件。再形态学 `open` 去噪 + `close` 补洞。
2. **连通域过滤**，对每个轮廓算四个量：
   - `area_ratio = 轮廓面积 / (W*H)`
   - `ratio = 外接框宽 / 外接框高`
   - `fill = 轮廓面积 / 外接框面积`
   - 质心 `(cx, cy)` 归一化坐标
3. **五条判据同时满足才算候选**：
   | 判据 | 典型值 | 作用 |
   |---|---|---|
   | `AR_LO <= area_ratio <= AR_HI` | 0.03 ~ 0.15 | 排除小杂物与大块粘连 |
   | `ratio <= RATIO_MAX` | 2.0 | 排除横向细长杂物（边框、线缆） |
   | `fill >= FILL_MIN` | 0.35 | 排除弧状/细长物（填充率极低） |
   | `|cx-0.5|,|cy-0.5| <= CENTER_BOX` | 0.33 | **排除四周固定杂物** |
   | 框离画面边缘 `>= EDGE_MARGIN` | 0.04 | 避免归一化坐标触 0/1 被平台拒 |
4. **择优**：`score = area_ratio - CENTER_W * 到中心距离`，取最大。
5. **输出框**：**紧贴外接框，不外扩**（设计要求：框贴合目标，宁紧勿松；
   松框会稀释训练信号）。归一化后**夹到 (1e-4, 1-1e-4)** 防触 0/1。

## 关键踩坑（务必读）

### 1. 四周有固定杂物时，单靠面积阈值一定翻车
固定机位照片的**四角 / 四边**常有反复出现的杂物（设备边框、线缆、手环、色卡），
它们的面积占比可能恰好落在真实目标区间（本例 2%，真实工件 6%）。
**必须加"中心区约束"**（`CENTER_BOX`）把它们一刀切掉，而不是靠调面积上下限。
典型杂物位置：`box=(20,0,74,95)`（左上角）、`box=(433,405,47,75)`（右下角）、
`box=(348,0,132,159)`（上方）——这些坐标在数百张图里几乎完全一致。

### 2. 固定杂物 vs 真实目标：靠"位置"而非"大小"区分
同一把杂物可能在部分图里面积**恰好等于**真目标。此时唯一可靠的判据是
**质心是否在中心区**。先按面积排序列出候选清单（`calibrate.py` 会做），
你会发现杂物坐标高度可重复，真目标坐标则随拍照抖动。

### 3. `ratio` / `fill` 过高会误杀真目标
本例中"深色线缆搭在目标上"会让外接框横向拉长，`ratio` 从 0.9 涨到 1.8，
但**框高几乎不变**（真实目标 140~160px）。若把 `ratio` 卡在 1.4，会误杀 16 张真目标。
→ 所以 `ratio` 上限要放宽（2.0），改用**中心区 + 填充率**来做主判据。

### 4. 归一化坐标触 0 或 1 会被平台判为非法
目标贴到画面边缘时，`(x0)/W` 可能正好等于 0.0。Ultralytics 平台校验要求
坐标严格在 `(0, 1)` 开区间 → 会报 `range` 错误。**输出前统一 clamp 到 `1e-4 ~ 1-1e-4`。**

### 5. 不要在脚本里做目录级删除（`shutil.rmtree` / 批量 `os.remove`）
沙箱与用户授权都会拦截批量删除，导致脚本**中途失败但已写了一半**。
→ 每次输出到**全新目录**（如 `_ds_v2`），或让用户自己删。保持脚本幂等、可重跑。

### 6. 目标可能离中心有一定偏移
不要用"必须以画面中心为中心点"做假设。本例 `cx/W` 实际范围 `0.19~0.81`。
中心区约束取 `|cx-0.5| <= 0.33` 较为稳妥；过紧（如 0.2）会误杀。

### 7. 训练/验证划分要随机且固定种子
同一批连拍照片之间高度相似，随机划分会有泄漏。若用户在意，应按"拍摄场景/连拍段"
分组切分，而不是按单张随机。默认 `VAL_RATIO=0.15`、`SEED=42`。

### 8. "框看起来偏大"——先判断是不是旋转导致的几何死结（别瞎调阈值）
用户反馈"框还是大"时，**先量三个数**再动手：
```
凸包面积 / 轮廓面积   接近 1.0（实测 1.022）-> 轮廓本身干净、无毛刺
正轴框面积 / 轮廓面积 实测 1.46
正轴框面积 / 旋转框面积 实测 1.19
```
判读：
- 凸包≈轮廓 → **轮廓没问题**，框大不是分割质量差。
- 正轴框/旋转框 > 1.15 → 是**目标旋转**导致的。正轴对齐框必须覆盖轮廓全部点，
  其边界就是轮廓 x/y 的 min/max，**已经是数学下限**；斜放方块在 45° 时框面积可达 2 倍。
- 此时**任何阈值/算法调整都不会让框更小**，唯一能贴合的是 OBB 或分割多边形。

实测排除了两条常见误判（不要重复踩）：
- **阴影**不是元凶：把 `V<VAL_MAX` 暗部条件去掉，轮廓面积只变 **0.4%**。
- **形态学重建（距离变换取种子 + 在前景内重建）救不了细线粘连**：
  重建会把"与种子相连"的前景**全部拉回来**，线缆照样在，框面积变化 ~0%（实测 +0.4%）。
  要剔除粘连必须**断连**（开运算/分水岭），而不是重建。

**结论模板（可直接给用户）**：框 == 轮廓紧致正轴框（实测偏差 ≤0.001 px），
已无可紧空间；若要更贴合只能上 OBB，而 OBB 需用户明确同意。

### 9. Windows 中文/非 ASCII 路径：`cv2.imread` 会静默返回 None
不是抛异常，而是打一行 WARN 后返回 `None`，表现为"整批图都读不到"却查不出原因。
**必须**统一用：
```python
def imread_u(p):
    return cv2.imdecode(np.fromfile(p, dtype=np.uint8), cv2.IMREAD_COLOR)
```
`shutil.copy2` / `zipfile` 对中文路径正常，只有 OpenCV 的 `imread/imwrite` 有问题。
（本 skill 的三个脚本已内置该校验。）

### 10. 高饱和异物（手指/肤色）会与目标抢候选，且面积可能更大
实测：三百九十余张里有 3 张出现"手指入画"，其中 **2 张手指面积 > 目标面积**，
若只按"取最大候选"就会把框标在手上。判据设计要点：
- **不要只靠取最大面积**，必须叠加几何过滤。
- **边缘余量是剔除异物最有效的判据**：异物从画面外伸入 → 必然贴边；
  台面上的目标一般不贴边。本例 `--edge-margin 0.03` 一次清掉 2 处错标。
- 肤色与彩色工件同属高饱和，**饱和度规则无法区分**，只能靠几何。

### 11. 目标不一定在画面中心——中心约束要按实测放宽
该批目标居中（`cx` 0.19~0.81，`CENTER_BOX=0.33` 可用）；
形状E 这批目标随转台到处走（`cx` 0.09~0.78），沿用 0.33 会**误杀**。
规则：**先用 `calibrate.py` 量出质心范围，再定 `CENTER_BOX`**（本例放宽到 0.45）。
另外：背景若有**深色机构件**，暗部规则 `V<VAL_MAX` 会把机器当前景 →
应传 `--val-max 0` 关闭它，只保留饱和度规则。

### 12. 肤色手指：用"候选级饱和度"剔除，并备好高阈值回退【本项目高频坑】
相机夹具/人工干预会让**手指入画**。肤色与彩色塑料同属高饱和，色相/几何都难分，
但**饱和度可分**（实测）：

| 类别 | S 中位数 |
|---|---|
| 肤色手指 | **90 ~ 118** |
| 绿色塑料件（最低的一类） | 133 ~ 148 |
| 蓝色/红色塑料件 | 157 ~ 213 |

**两级判据（推荐默认）**：
1. **mask 用低阈值**（`--sat-min 60`）→ 目标轮廓完整，不会向内咬。
2. **候选级过滤** `--cand-s-min 125` → 剔除 S 中位数偏低的手指候选。
3. **高阈值回退** `--fallback-sat 135` → 当严格判据后**一个候选都不剩**时
   （典型：手指与目标粘连成一个块，且块中位数被手指拉低），
   用高阈值重分割，从粘连块里捞出高饱和的"目标核心"。

**当目标饱和度整体很高时，直接提高 mask 阈值是更强的杠杆**：
形状A（S≥169）用 `--sat-min 130` 即可彻底断开粘连，且不侵蚀目标。
**但必须先扫描确认不侵蚀**——形状H里的绿色件 S 仅 133，同样提到 130 会把
面积从 5.36% 削到 2.96%，框咬进目标且被面积下限卡掉（实测漏检 14 张）。

### 13. 不要用"相对中位数取核心"来判断粘连（已证伪，勿重复）
曾设想：块内 `S >= 块中位数` 的"核心"bbox 若明显小于整块 bbox，就说明含干扰物。
**实测在 100% 的干净样本上也触发**（形状G cam_001203：blob 149×155 → core 109×110，
缩 48%，但那是个干净的形状G）——因为纯色物体最饱和的像素天然集中在中心。
→ 该启发式**无效**。教训：任何新判据都要先在**全清样本**上跑一遍，再上生产。

### 14. 工作目录必须每次唯一，否则旧文件会被打进 ZIP
复用同名工作目录（如两个数据集都叫 `_class_9_ds`）会把上一次的残留文件一起压缩，
症状是 `images` 与 `labels` 数量不等（实测 967 vs 1166）。**每次用新目录**。

### 15. 判据适用性自查（三条，缺一不可）
- **目标会不会贴边？** 会贴边就**禁用 `--edge-margin`**（形状A实测 12 张贴边，
  用 0.03 会误杀真目标）；不会贴边则边缘余量是剔除异物最省事的判据。
- **目标饱和度最低能到多少？** 决定 `--cand-s-min` 与 mask 阈值能否提高。
- **背景有没有深色机构件？** 有则 `--val-max 0` 关闭暗部规则。

### 16. 镂空/开孔物体（空心形状F）：外轮廓天然含孔，bbox 反而是对的
实测空心形状F 一百九十余张：
- **孔洞不会把候选切碎**——`RETR_EXTERNAL` 给的是外轮廓，`contourArea` 算的是
  外轮廓围成的**整块面积（含孔）**，`boundingRect` 也是整个物体的范围 → 这正是我们要的框。
- 孔洞真正暴露在 mask 里的帧很少（7/195），且孔洞面积占外轮廓 **≤0.7%**；
  因为从斜角看，圆筒内壁同样是饱和色，孔并不会变成"背景"。
- 若孔洞里面透出的是**低饱和背景**（如白台面），mask 会变成环形，
  但外轮廓照旧给出完整外接框，**仍不需要特殊处理**。
→ 结论：镂空件在这个流水线里**无需额外逻辑**；真正要防的是"孔内是背景"
   被 `--cand-s-min` 之类的中位数统计干扰（孔占比极小时不影响中位数）。

### 17. 标签级"异常框"阈值必须按物体尺度设，不能一套通用
同一阈值在不同物体上结论完全相反：`框面积 > 0.25` 这一条
对形状G/形状H/形状E是**真异常**（它们只占 5~12%），
对**空心形状F却是常态**（它本身就占 13~21%，框面积可达 0.30）。
→ 扫描异常时先看该物体的面积分布，再用"p95 × 1.5"之类的相对阈值；
   否则会把 16% 的正常帧误报成异常。

### 18. `--fallback-sat` 要避开低饱和颜色件的上限
实测：低饱和色件的 S 上限约 145 时，回退阈值取 140 面积掉 40%，
取 150 面积掉 75%（框已咬进目标）。**回退阈值必须比该目标饱和度上限低 15 以上**。
定法：用一张"干净的低饱和色"帧做对照，扫阈值看面积何时开始明显下降。

### 19. 同一目录可能混有两批拍摄——先按命名前缀分组统计
实测形状I目录含两种命名：`cam_*(279)` 与 `batch_b (N)(114)`。
两组的颜色（红 vs 绿）、饱和度中位数（174 vs 142）、面积中位数（5.10% vs 3.51%）、
以及**是否含手指**（前者 0 双候选，后者 59 双候选）全都不同。
→ 标定前先 `ls | sed 's/[0-9].*//' | sort | uniq -c` 看命名构成；
   若有多组，**分别统计**再定参，否则一组的特性会掩盖另一组的问题。

### 20. 暗色低饱和件与手指在 S/H 上完全重叠——必须"双阈值分工"
实测形状I：**暗红工件的 S=92~119、H=7~11**；**肤色手指 S=90~118、H=0~25**。
即饱和度与色相**都无法区分**二者。此时单阈值必然二选一失败。

**正确做法：两个阈值各司其职**
- `--cand-s-min 125`（高）：只用于**剔除手指/手掌**——手指一定被拒。
- `--fallback-sat 85`（低）：**仅在严格判据后一个候选都不剩时**触发，
  用来救回"暗色工件是唯一候选"的帧（本例 5 张 S 92~123 的真工件）。

为什么这样能成立：暗色件与手指很少同时是"唯一候选"且暗色件更小；
一旦严格判据能选出一个候选，就绝不会走回退，回退的低阈值因此不会放错手指。
**前提**：回退阈值必须**低于**真实工件饱和度的下限（本例 85 < 92），
且要确认"唯一候选=手指"的帧不存在（本例不存在）。

### 21. 固定位置的角落异物：用 fill / area 剔除，别急着动中心约束
形状I数据里左下角总有一条**橙色线缆弧**（第二候选）。
它的特征不是位置而是形状：**fill 仅 0.13**（工件 0.52~0.78），面积 1.1%（工件 2.8%+）。
→ 现有 `--fill-min 0.35` 与面积下限就已将其排除，无需为它专门收紧 `--center-box`。

### 22. 标签级异常要用"相对阈值"，且边界帧务必目视
用 `p95 * 1.6` 作相对阈值扫形状I，仅 1 帧超阈（cam_000414, 0.138 vs 0.136）。
目视 + 算术双重确认它是**俯视角度的工件**（框面积 0.138 × fill 0.75 ≈ 10.4%
= 本次构建的最大轮廓面积，完全自洽）→ 正常帧，不是缺陷。
**边界值不要靠猜**：先算 `框面积 × fill` 是否等于实测轮廓面积，再去渲染核对。
