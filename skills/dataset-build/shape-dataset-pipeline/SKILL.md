# Shape Dataset Pipeline（照片 → 标注 → 合并 → 平台可导入 ZIP）

## 这个 skill 解决什么

一条链路，五种任务：

| 任务 | 命令 |
|---|---|
| ① 标定一个数据集该用什么阈值 | `probe.py` |
| ② 单个文件夹标注 → 平台 ZIP | `annotate.py --src --cls` |
| ③ 多个数据集合并成一个包（含灰度增广） | `annotate.py --jobs` 或 `merge_pack.py` |
| ④ 把已有的多个单类 ZIP 合并重编号 | `merge_pack.py --job` |
| ⑤ 上传平台前自检 | `verify.py` |

前置依赖：`numpy opencv-python pyyaml`（要跑最强校验再加 `ultralytics`）。
本机（Windows / Store Python 3.13）已具备：numpy 2.4.4、cv2 5.0.0、yaml 6.0.3。

## Quick Start

```bash
# 0) 先标定（不要跳，也不要凭直觉设阈值）
python scripts/probe.py --src "./work/batch-a" --out ./work/out

# 1) 标注 + 打包（默认参数是 8 个真实数据集上验证过的）
python scripts/annotate.py --src "./work/batch-a" --cls class_2 --zip "./work/batch-a.zip"

# 2) 校验（装上 ultralytics 时会在临时目录真跑一遍 check_det_dataset）
python scripts/verify.py --zip "./work/batch-a.zip"

# 3) 多数据集合并 + 每类 20% 灰度增广
python scripts/annotate.py --jobs jobs.json --zip "./work/shapes-7cls.zip" --gray-frac 0.20

# 4) 合并已有的单类 ZIP（自动兼容新旧两种目录布局）
python scripts/merge_pack.py --job "./work/batch-b.zip:class_7" --job "./work/batch-c.zip:class_9" \
        --zip "./work/merged.zip" --gray-frac 0.20
```

`jobs.json`：
```json
[{"src": "./work/batch-a", "cls": "class_2"},
 {"src": "./work/batch-b",     "cls": "class_7"},
 {"src": "./work/batch-d",   "cls": "batch_b"}]
```
**类别 id 按 jobs 列表顺序编号 0..N-1**，这个顺序就是最终 `data.yaml` 的 names 顺序。

产出（每次都会写）：
```
<zip>                        平台可导入包
<zip名>_report.txt           命中/未命中/每类统计/固定杂物清单
<zip名>_report.json          同上的机器可读版
<zip名>_records.json         逐图清单（status/clip/area/sat0/thr），用于筛可疑帧
<zip名>_audit/audit.png      抽样标注图 —— 交付前必须肉眼过一遍
<zip名>_audit/flagged.png    裁剪率最高 / 面积最大的帧
```

## 判据：阈值从哪来（不要背参数，要会量）

`probe.py` 会量出三组数，它们决定一切的取法：

| 量 | 典型实测（8 个数据集） | 用途 |
|---|---|---|
| 背景 S(p95) | 8 ~ 16 | 决定 `sat_lo` 下界（必须远高于它） |
| 阴影/倒影 S(p50) | 23 ~ 48 | 决定 `sat_lo` 下界（**必须高于它**） |
| 目标 S(p05) | 64 ~ 102 | 决定 `sat_lo` / `cand_s_min` 上界（不能切到本体） |
| 目标 S(p50) | 162 ~ 183 | `tighten_k * S0` 的基准 |
| 面积比 p50 | 2.5% ~ 21% | 决定 `area_lo/area_hi`（大件要放到 0.35） |
| 质心范围 | cx 0.09~0.81 | 决定 `center_box` 放宽到多少 |
| 贴边帧数 | 0 ~ 66 | 不为 0 就必须 `edge_margin=0` |

**自适应阈值（本 skill 的核心，取代固定阈值）**

```
thr = clip(round(tighten_k * S0), sat_lo, tighten_hi)      # 默认 k=0.5, hi=130
S0  = 该帧目标候选在 sat_lo 下的饱和度中位数
```
- 阈值**高于所有阴影/倒影**（≥60）→ 阴影与倒影自动排除，不需要任何额外规则；
- 阈值**低于目标自身最暗的 5%**（0.5×S0 ≈ 81~92）→ 只削掉不足 5% 的暗边 → 贴合但不咬进本体；
- **收紧后必须验收**：算 `clip`（目标在 `sat_lo` 下的完整掩膜落在新框外的比例），
  `clip > clip_tol(0.10)` 就**放弃收紧**，退回 `sat_lo` 的框。
  这一条是必须的：暗色件（S0≈92）如果硬套固定阈值 130，`clip` 会到 31% —— 那不是贴合，是咬进目标。

**三层回退（应对手指 / 暗色件）**

| 层 | 条件 | 做法 |
|---|---|---|
| strict | 默认 | `sat_lo=60` mask + 候选级 `S ≥ 125`（剔手指） |
| 回退 1 | strict 后一个候选都不剩 | 依次试 `120 → 135 → 150`，且关闭候选级过滤 → 从「手指+目标粘连块」里捞出**目标本体** |
| 回退 2 | 仍为空 | `55`（仍高于阴影）→ 救暗色工件（实测 S0 92~123） |

为什么这样成立：手指 S 只有 90~118，暗色件 S 92~119 —— **两者在 S 和 H 上完全重叠**，
单阈值必然二选一失败。分工后，`cand_s_min=125` 保证手指一定被拒，
而低阈值回退只在「严格判据全空」时触发，此时暗色件是唯一候选，不会放错手指。

**固定杂物自动抑制（把「人工看标定清单」自动化）**

固定机位照片的四角/四边常有反复出现的异物（设备边框、线缆、色卡）。
`build_dataset` 会统计所有已选框的中心，找到「出现 ≥ max(8, 10% 张数) 次、
位置几乎不重复抖动、且离画面中心 > 0.30」的簇 → 判定为固定杂物 →
对受影响的帧重跑标注（把这些位置加入排除表），并已选的框换成下一个候选。
报告里的 `可疑固定杂物（已自动抑制）` 段落会列出簇位置与出现次数。
用 `--no-suppress-fixed` 可关闭。

## 平台打包规范（三条都会让导入直接失败，务必遵守）

1. **目录结构**必须是 `train/images` + `train/labels` + `val/images` + `val/labels`
   （按 split 分目录）。本地训练常用的 `images/train` 平台不认，
   报错条款是「需要训练集划分：将 train/ 文件夹添加到数据集结构中」。
2. **`data.yaml` 不写 `path`**。写了会被按**当前工作目录**解析，换机器/换解压位置即
   `missing path ...`。省略后，库与平台都以 yaml 自身所在目录为根。
3. **文件名只用 `[A-Za-z0-9._-]`**。源目录里的 `disanpi (117).jpg`、`batch_b (79).jpg`
   这类名字（实测两千余个）平台会拒，`sanitize_name()` 统一清洗。

外加两条环境坑：

4. **`data.yaml` 里绝不能出现字面量 `/n`**。某些字符串通道会把源码里的换行转义破坏成
   `/n`，生成的 YAML 非法且**看不出异常**（字节级才可见）。
   本 skill 的所有文本一律用 `LF = chr(10)` 拼接 + 按 bytes 写入，源码内不出现反斜杠转义。
5. **中文/非 ASCII 路径下 `cv2.imread` 静默返回 None**（只打一行 WARN），表现为「整批读不到」。
   一律用 `imread_u()`（`np.fromfile` + `imdecode`）。

上传前请务必跑 `verify.py`：CRC、顶层结构、配对、标签五元组、坐标开区间、
文件名合规、yaml 解析，并且**安装了 ultralytics 时会真跑一次 `check_det_dataset`**。

## 灰度增广（可选）

`--gray-frac 0.20`：每类随机抽 20% 的图，BGR→GRAY→BGR 后**新增**一份（保留彩色原图），
灰度版按 85:15 分入 train/val（`--gray-val-ratio` 可调），文件名加 `_g` 后缀。
它强制模型不能只靠颜色分类 —— 这是「同形状不同颜色」数据集上非常有效的正则。
实测：灰度版 `S(p99) = 0.0`，确认彻底无色。

## 合并多个已有包时的两个真实坑

1. **类别 id 冲突**：每个单类包的 id 都是 0，直接拼会退化成单类 →
   `merge_pack.py` 按 `--job` 顺序重排为 0..N-1。
2. **文件名撞车**：多个数据集都用 `cam_*.jpg` 命名，直接拼会覆盖 →
   统一加 `<cls>__` 前缀（灰度再加 `_g`），并做唯一化兜底。
3. 源包布局**新旧都兼容**（`images/train` 与 `train/images` 都能读）。

## 踩坑清单（前 20 条与 `center-object-to-yolo-zip` 同源，此处只列本链路新增的）

- **clip 指标必须对照「与框重叠最多的连通块」，不能取全局最大块**：画面里常有比目标
  更大的异物（手指、手掌、线缆），此时全局最大块与框**零重叠**，clip 会恒等于 `1.000` ——
  这是**指标失真，不是标注错误**（实测 7 个数据集四千余张里有 10 张踩到，逐张看图后全是
  正确标注）。`blob_for_box()` 已按重叠量选块。任何"看起来很吓人"的报警，先用这个思路
  排除指标本身的问题，再判数据。
- **候选级下限 `cand_s_min=125` 会拒掉「低饱和目标」**：实测 7 个数据集四千余张里有 13 张
  （0.31%）目标的饱和中位数只有 **102~124**（淡绿/浅蓝件），被严格层拒 → 走高阈值回退 →
  框略紧。诊断：看报告里的 `阈值路径` 与回退帧清单；若目标确实偏淡，
  下调 `--cand-s-min 100~118`（**不要低于手指上限 118**）。这 13 张已逐张验证：
  框都完整包住目标的高饱和核心，属可用；只有 1 张（`cam_002605`）框到本体约 75%。
- **`--fallback-sat` 必须避开低饱和颜色件的上限**：实测某批低饱和目标 S 上限约 145，
  回退取 140 面积就掉 40%、取 150 掉 75%（框咬进目标）。**回退阈值要比饱和度上限低 15 以上**。
- **同一目录可能混两批拍摄**：先看 `name_prefixes`。实测形状I目录 `cam_*(279)` 与
  `batch_b (N)(114)` 的颜色、饱和度中位数、面积中位数、是否含手指全都不同；
  混在一起统计会互相掩盖。
- **不要用「相对中位数取核心」判粘连**（已证伪）：纯色物体最饱和的像素天然集中在中心，
  该指标在 100% 的干净样本上也触发（形状G 149×155 → 109×110，缩 48%）。
- **标签级异常阈值按物体尺度设**：`框面积 > 0.25` 对形状G/方块是真异常，
  对空心形状F（本身就占 13~21%）却是常态。用 p95×1.5 之类相对阈值。
- **镂空件（空心形状F）无需特殊处理**：`RETR_EXTERNAL` + `contourArea` 天然给出含孔的整块外接框。
- **框看起来「偏大」先量三个数**（凸包/轮廓、正轴框/轮廓、正轴框/旋转框），
  再决定是不是旋转几何死结 —— 详见 `center-object-to-yolo-zip` 第 8 条。
- **工作目录每次唯一**：复用同名目录会把上次残留一起压进包，症状是 images/labels 数量不等。
- **脚本里不要做目录级删除**：沙箱与用户授权都会拦截，导致脚本跑一半失败。输出到新目录即可。
