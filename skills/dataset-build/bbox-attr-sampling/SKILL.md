# 用检测框内像素判定属性：采样与判据规则

## 何时用

- 用 bbox 内的像素投票判颜色 / 纹理 / 亮度 / 有无孔洞。
- 对象可能是**镂空、开孔、带洞、透明、强反光**的（中心会看到背景或高光）。
- 现象是"某个形状才判错""偶尔判错""小目标判错"。

## 核心认识：采哪里都是在赌框的精度 —— 两个方向都会输

| 采样位置 | 赌的是什么 | 什么情况下必然输 |
|---|---|---|
| **框中心** | 赌"框中心是物体" | 镂空（中心是洞）、正面高光（中心是反光点）、透明 |
| **框内侧边缘** | 赌"框紧贴物体" | **检测框偏大**；**物体斜放**（外接框的边中点恰好是离物体最远的位置） |

**两个方向都不能选。** 因为检测框（尤其 detect 轴对齐框）天生不精确：框会包住凸包，
斜放的细长物体会让"外接框的边中点"完全落在背景里。
**实测佐证**：某工程把中心采样改成"边中点块"后，镂空问题解决了，
但在"框比物体大 35%"的场景下从判对变成判错（静默判成黑色），
在"斜放细条 + 彩色底"场景下也从判对变成判错。

> 结论：**不要用几何位置去区分材质和背景。** 位置只在"框精确"时才携带信息。

## 正解：用像素自身的属性把背景识别出来，然后让它弃权

```
运行期每个采样像素：
    if 与背景参考的距离 < 容差:
        弃权（不计入任何票，也不进分母，且跳过后续最贵的计算）
```

为什么这是正解：
- **不依赖框的精度**：无论框偏大还是物体斜放，背景像素都被识别出来干掉了。
- **不依赖物体姿态**：背景就是背景，与物体怎么摆无关。
- **对实心物体也是正收益**：顺手修掉了长期存在的"框边缘蹭到背景"污染。
- **可能让总 CPU 下降**：背景弃权放在属性计算（HSV 转换、分类）之前，
  省掉的正是最贵的那一步。实测某工程 HSV 转换次数降到基准的 **7%**。

背景参考从哪来（按成本排序）：
1. **全自动**：检测到"目标数为 0"的帧 = 画面里只有背景 → 用这些帧估计（限流到 1 次/秒）。
2. 半自动：开机做一次"空场景"采集。
3. 手工：直接填一个 RGB。

容差要现场实测：背景有亮度渐变时，容差必须覆盖渐变幅度。
**容差过小 = 背景漏过（污染票）；容差过大 = 物体被误弃权（证据不足）。**

## 判据的三个必然陷阱

### 陷阱 A：族间判据不对称 → 少数票压过多数票

常见写法：某族分支的"占比"分母只算**该族票数**，不是全部像素。
后果：**12 个彩色像素能压过 500 个黑色像素**（实测）。
**自检**：构造"96% 主色 + 4% 异色小块"的合成图，看结论是否被那 4% 带走。5 行代码就能写完，务必做。

### 陷阱 B：早停会让结论依赖扫描顺序

"票数达到 N 就 break"——扫描通常行优先，于是**先扫到的那部分像素决定结论**。
早停往往是**性能生命线**（尤其是嵌入式 CPU），不能简单删掉。
**正确处理**：保留早停，但**同时加一条"采样点数硬上限"**（见陷阱 C），
并让两条规则取先到者。**不要删早停**，删之前先量 CPU。

### 陷阱 C：弃权/跳过后，原来的早停条件可能永不触发

**这是最隐蔽的一个。** 加了"背景弃权"之后，如果早停条件是"**某族票数**达到 N"，
而弃权恰好把这族的票源干掉了，早停就永远不会触发 → **扫满全场**（实测点数是原来的 1.8 倍）。

两个必须做的修正：
1. **加采样点数硬上限**（如 `MAX_POINTS = 64`），无条件停。
2. **把上限检查放在循环体最前面** —— 放在后面会被 `continue`（弃权路径）绕过，
   表现为"整片是背景时上限永远不触发"。**这个 bug 实测踩过。**

## 验证做法（必须做，且可离线）

1. 写**合成图**脚本：纯色 + 居中方形洞，参数化洞边长与洞内颜色。
2. **只读导入**项目的真实判定函数（不要重写一份，否则验的不是同一个东西）。
3. **先写出"采样区边长 = 比例 × 框边长"的预测失效边界**，再用实验验证 ——
   边界逐值吻合才算证明（不是事后拟合）。
4. 场景必须覆盖三类，缺一不可：
   - **几何免疫类**：镂空 / 开孔 × 不同洞内颜色
   - **退化回归类**：实心纯色（确认没退化）
   - **框不精确类**：框比物体大 20~35%、物体斜放、背景带渐变 ← **最容易被漏掉的一类**
5. 指标要分开报：**判定正确率 / 静默判错数 / 判不出数 / 采样点数 / 属性计算次数**。
   "静默判错"（拿着错的属性照发）与"判不出"（走兜底或报未知）**严重程度差一个量级**，
   混在一起报会掩盖真实风险。

## 汇报纪律

- **不要用一个场景的正确率去推普遍结论。** 修 A 场景的方案可能在 B 场景更差；
  必须同时给出回归用例与"框不精确"用例。
- 承认被否决的方案时，**用数据证明对方对**（哪几个场景、从对变错），不要只是口头认错。
- 如果某方案的理由是绑定在另一个前提上的（如"删早停更快"绑定在"采样点数从 225 降到 64"），
  一旦那个前提被否，**要主动指出该理由同时失效**；否则就是用失效的理由硬撑。
- 如实标注已知上限：新方案在什么条件下也会失效（如洞过大、容差覆盖不住背景渐变）。
