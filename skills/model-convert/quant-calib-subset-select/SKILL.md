# 量化校准子集筛选（强化小目标 / 密集场景，保精度）

> **适用**：PTQ（INT8）校准集挑选。用户症状通常是「float/训练模型能检出远端小物体，量化上机后召回明显变差」。  
> **核心命题**：量化范围（per-tensor scale）由**激活**决定，激活来自**每一个实例**。所以校准集必须按**实例级**分布设计，而不是按图像级。

---

## 一、机理：为什么量化后小目标先掉

INT8 PTQ 的 per-tensor scale 由校准时的激活范围（max 或高位分位）决定。若校准集被「大而近、高对比」的目标主导：

1. 范围被大目标拉宽 → 量化步长变粗 → 小目标那些**幅值更小**的响应只剩很少有效级数，被压到检测阈值以下；
2. FPN 高分辨率分支（stride 8，管小目标）在校准中见到的小目标信号太稀薄，动态范围被背景噪声主导。

**结论**：校准集要在**匹配部署分布**的基础上，**刻意提高小目标/密集场景的实例占比**，同时**保留足量大目标样本守住上界**（否则大目标激活被截断，整体精度反而下降）。

---

## 二、五条第一性原则（踩过坑总结，务必先看）

1. **必须按「实例」而非「图」做配额**  
   一张含 1 个小目标的密集图，其余 5–10 个目标仍是大/中目标。按「图像 min_side」分层，实例级小目标占比几乎不动（实测 7.1% → 7.9%，白干）。  
   → 直接在**实例尺度直方图**上做目标配额。
2. **清晰度（Laplacian 方差）不能当「远端/模糊」的代理**  
   实测：低 lapvar 样本的目标边长中位数是 **169 px（大目标）**。因为白底/灰底棚拍背景平滑、边缘少，lapvar 天然低；而多物体桌面场景边缘多，lapvar 反而高。  
   → lapvar 只能用于**同源数据内**的相对去重/取最优，**绝不能**用来判断「是否远端」。
3. **单目标优化必然牺牲其它目标**  
   只压实例尺度直方图 → 单物体棚拍大目标图涌入填大尺度档 → 密度中位数下降、长尾类别掉到 0.4×、部署域占比反降。  
   → 必须**多目标同时约束**，用 **maximin（瓶颈）贪心**：评分 = min(各约束的归一化满足度)，每次选让**最差约束**改善最多的图。**不要用加权求和**（会拿一项换一项，容易压垮某一维）。
4. **必须先排除 `test` 划分**  
   校准会改变量化后模型，用测试集校准会让后续测试指标虚高（数据泄漏）。用 train+val。
5. **必须先去近重复**  
   同一采集会话的连续帧会大量近重复（实测剔除 278/1258 = 22%）。不去重会白占配额并让范围偏向少数场景。用 dHash Hamming ≤ 4，同组保留最清晰的一张。

## 三、标准流程

### Step 0 — 数据源画像（关键，别跳过）

先按**文件名模式 × 分辨率 × 目标数 × 尺度 × 清晰度**给数据分域。真实项目的数据集常是**多个来源拼接**，且**小目标往往只存在于其中一族**。

```python
# 典型：三种来源，特征差异极大
# A 时间戳_device_*   416px 白底单物    n中位 2  min_side中位 154px
# B 其他/640原生       640px 桌面多物    n中位 6  min_side中位  51px  <- 部署域
# C 类别名_*          416px 灰底单大物   n中位 1  min_side中位 273px
```

**随机抽样会把部署域压到自然占比以下** —— 这就是「量化集质量不高」的根因。

### Step 1 — 提取特征（每张图）

- 实例尺度：四边形 shoelace 面积 → 等效边长 = `sqrt(area) * input_size`（换算到模型输入分辨率，如 640）
- 目标数 `n_obj`
- 类别集合（one-hot）
- 分辨率、文件名来源族
- dHash（去重）、Laplacian 方差（同源内相对质量）
- 域标记：`deploy = (n_obj >= 3 and min_side < 130)`

### Step 2 — 池构造 + 去重

```
全量 → 剔除 test 与零目标图 → dHash(Hamming<=4) 去近重复（保留最清晰）
```

### Step 3 — maximin 多目标贪心

定义 4–5 条**覆盖下限**（举例，按数据调）：

```
M1 小目标(<50px)实例占比 >= 0.09      # 池自然 0.071 -> 提升远端召回
M2 密集图(n_obj>=6)占比   >= 0.40      # 池自然 0.296 -> 多目标能力
M3 部署域图占比           >= 0.45      # 域匹配
M4 大目标(>=130px)实例占比 >= 0.20      # 池自然 0.264 -> 守住量化上界
M5 每类实例份额 >= 0.8x 池份额         # 类别不退化
```

每次：

```python
m1 = (small_inst/总inst) / T_SMALL
m2 = (密集图数/图数)     / T_DENSE
m3 = min_over_class( 类份额 / (T_CLASS*池类份额) )
m4 = (deploy图数/图数)   / T_DEPLOY
m5 = (large_inst/总inst) / T_LARGE
score = min(m1,m2,m3,m4,m5)          # 瓶颈
picked = argmax(score)               # 平手用质量分裁决
```

质量分（平手裁决）建议：`2.0*deploy + 1.0*类别稀有度 + 0.5*清晰度分位 + 0.3*min(n_obj,10)/10`，并跳过与已选图 Hamming ≤ 6 的候选（冗余抑制）。

### Step 4 — 目标可行性扫描（强烈建议）

**先用一组目标网格跑 sweep**，只保留「所有下限都能达成」的组合再定稿。否则会拿到一个达不到的目标、结果偏科。判定「达成」时留 0.5–1% 容差。

### Step 5 — 类别修复（可选）

对份额不足的类别做「换入含该类别的候选 / 换出质量最低且不含该类的已选图」迭代，**只接受让最差份额变好的解**（否则震荡）。注意：若结构性缺数据，此步会一动不动——属正常，说明该类在目标域中确实稀少。

## 四、验证（必做，否则等于没做）

### 4.1 上界覆盖检查 —— 证明「无损精度」前提成立（最关键）

```python
# 必须核对：大目标实例的绝对数与高分位不能塌
P99(池) vs P99(子集)          # 偏差应 < 5%
(>=130px 实例数) 子集 / 随机基线   # 应 >= 0.9
```

实测合格例：小目标 <50px 实例数 1.69×（81 vs 随机 48），同时 `>=130px` 实例 183 vs 随机 184、P99 317.8 vs 池 318.7 → 两侧同时成立。

### 4.2 对照表（子集 vs 全池 vs 随机基线）

报告：小目标实例数与占比、密集图占比、每图中位目标数、部署域占比、类别最少实例数、分辨率构成、以及与小目标相关的**绝对数**（绝对数比占比更能说明可用性）。  
注：与全池的 KS 距离**刻意不为 0**（实测 0.059 vs 随机 0.030），这是设计意图，但需说明 4 个尺度档均有配额、未被压成单峰。

### 4.3 人工核验预览拼图

画 24 张抽样拼图（按实例尺度着色：绿=小 / 黄=中 / 蓝=大）并**亲眼看一遍**。这一步能抓到统计指标抓不到的域错配。

### 4.4 编译期保真（本地）

去掉 `--fast` 重跑，让量化工具跑 precision_analysis，比较 NPU 仿真 vs float 的 cosine 相似度，应 ≥0.999。

### 4.5 实机对比（决定性）

同一批难例（含 <50px 且 n_obj>=5）分别跑旧/新校准模型：

```
1) 小目标召回 Recall@IoU0.5（仅统计 <75px 的 GT）  —— 最关键
2) 每图平均检出数 / GT 数                        —— 对应多目标需求
3) 整体 mAP50                                    —— 确认没为小目标牺牲整体
判定：Recall_small +>=3pt 且 检出率 +>=5% 且 mAP50 -<=0.5pt
```

**提示**：量化对小目标是**阈值效应**（要么明显改善要么基本不变）。若实机无变化，通常说明原问题不在校准集，应转向「补采集真实远端场景图」或提高输入分辨率重训。

## 五、数量建议

- 一般 **100–300 张**；池内去重后候选 ≥800 时取 **数百张**较稳（每个稀有格能取到 80+ 实例）。
- 校准只吃图像**激活统计**，不需要标注。
- 代价参考：Pulsar2 AX620E 下 数百张校准每遍约 40–60 秒（跑两遍），整体转换约 8 分钟。
- 清单按分层结果排序输出，方便用户用 `index` 截断成 120/300。

## 七、工程坑

- 大文件批量下载用 `python urllib` + `ThreadPoolExecutor(16)` + 重试（实测千余张/数十 MB 约 3.5 分钟）；沙箱内 `curl` 落盘可能被拦。
- CDN 签名 URL 常有 `Expires` 参数，**先检查有效期**再决定是「下载并用」还是「仅输出清单」。
- 四边形面积用 shoelace 公式，**坐标是归一化的**，换算像素要乘输入分辨率。
- Bash 沙箱可能出现 PATH 损坏（`ls/grep/wc/dirname: command not found`），命令前加 `export PATH="/usr/bin:/bin:$PATH"` 可恢复。
- 中途多次重构选择器时要**保留每版结果对照**（v1/v2/v3/v4），否则容易在「修好一个指标、弄坏另一个」之间反复。最终版定稿标准：所有下限达标 + 上界覆盖通过。
