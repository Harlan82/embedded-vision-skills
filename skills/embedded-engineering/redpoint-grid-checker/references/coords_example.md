## 读这张表要注意

1. **网格相对相机约旋转 45°**：表中的 "R1C1…R3C3" 是**网格内部的行列序号**，不是屏幕上的
   左上→右下。例如 R1C1=(298,112) 在屏幕上是**右上角**（x 很大）。请按你真实的物理 3×3 摆放，
   用 (实测X, 实测Y) 把每个点对应到你的物体上，不要直接把 R1C1 当成你的物理左上角。

2. **第 1 个点（R1C1）是最不可信的**：n=1、时间覆盖率 0.0% = 整段日志里只出现**1 帧**
   （第 1420 行）。这正是用户反馈"顶部只闪了一两帧"的那个点——疑似单帧闪现/误检。它的位置虽
   落在网格角上，但样本只有 1 个，±σ 为 0 只是因为无统计意义。**必须回原帧确认这个角到底有没有物体。**

3. **实测中心 vs 理想网格位怎么选**：
   - 实测中心 = 多帧检测的样本均值，是**实际检测位置的最优估计**（高斯抖动下最大似然）。
   - 理想网格位 = 假设严格成规则 3×3 时双线性拟合出的"该在的位置"，会平滑掉真实偏差。
   - 要核对"相机实际打在哪"，用**实测中心**；要得到"若摆放绝对规整应在哪"，用**理想网格位**。

4. **第 6、9 点（R2C3、R3C3）n 偏小（59、42）但覆盖率仅 16%/15.7%**：说明它们不是全程每帧都有，
   而是集中在日志后段（约第 1380 行之后）才稳定出现——可能是后半段相机/物体才进入稳定状态，
   或是前期被遮挡。它们位置拟合正常，但样本偏少，置信标为 medium。

5. **坐标绝对值仍未经验证**：以上结论只代表"点彼此成网格、抖动稳定"。是否真的对应你的物理
   摆放，必须回 MaixCAM 原帧（检测框叠加）核对（见 SKILL.md ⚠️ 警示）。

## 用法

```bash
python scripts/compute_coords.py
```
默认读同目录/指定 PATH 的日志，输出同样格式的表 + `coords_result.json`。
